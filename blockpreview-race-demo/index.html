BlockPreview — Stylesheet Race Condition

Replicates the race between fetchAndLoadStylesheets() and renderBlockPreview() in BlockPreview's Lit element. Both run concurrently; on fast machines the markup lands in the shadow root before the stylesheet is adopted — causing a flash of unstyled content that only disappears when DevTools slows execution down.

What's happening

Both elements use Shadow DOM and adopt their stylesheet via adoptedStyleSheets — exactly how BlockPreview works. In the buggy version, fetchAndLoadStylesheets() is fired without being awaited, so the preview markup renders concurrently. Whichever finishes first wins; without DevTools overhead the API response usually arrives before the CSS, leaving the block unstyled.

The fix stores the stylesheet fetch in a deduplicated Promise and awaits it at the top of renderBlockPreview(). CSS and the API call still run in parallel, but markup is never painted until both are ready.
